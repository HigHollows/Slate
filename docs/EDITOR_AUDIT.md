# Éditeur — audit et état (traitement de texte riche)

## 1. Audit de l'existant (avant ce chantier)
- **Moteur** : Tiptap 3 / ProseMirror. **Document** : Yjs (`@tiptap/extension-collaboration`) ; l'historique ProseMirror est désactivé, annuler/rétablir passent par Yjs.
- **Stockage** : `page_content` (SQLite) = `doc_state` (octets Yjs, source de vérité) + `content_json` (instantané ProseMirror de secours) + `text_plain` (recherche FTS5) ; cibles de liens extraites à l'enregistrement. Enregistrement par `SaveManager` (regroupement, reprise sur échec, vidage à la fermeture).
- **Blocs déjà là** : paragraphes, titres 1–3, listes (puces/numérotées/tâches imbriquées), citation, séparateur, code (sans coloration), tableau (non redimensionnable), encadré, mention de page, déplacement de blocs, menu `/`, barre flottante (gras, italique, souligné, barré, code, lien).
- **Hors ligne** : tout est local. **Supabase** : le contenu des pages n'est pas encore synchronisé (aucune sync), donc rien du cloud pour l'éditeur.

## 2. Décisions
- Moteur conservé (pas de remplacement). Le formatage est stocké **sous forme de valeurs validées** (`format.ts`) : identifiants de palette ou `#rrggbb`, identifiants de police (`sans|serif|mono|document`), taille entière 8–96 px, interligne parmi `1|1.15|1.5|2`. Aucune chaîne CSS libre ni HTML n'est stockée ; le CSS est produit au rendu.
- Couleurs de palette = variables CSS avec variantes claire/sombre ; couleurs HEX personnalisées éclaircies/assombries au rendu selon leur luminance (`data-lum`) pour rester lisibles dans les deux thèmes.
- Collage : les styles Word/Docs compatibles sont convertis (couleur rgb/hex, taille px/pt, famille de police), le reste est ignoré ; scripts, gestionnaires d'événements, iframes, `position`, URL `javascript:` sont éliminés par le schéma ProseMirror (testé).
- Raccourci du lien : **Ctrl/Cmd+Maj+K** (Ctrl/Cmd+K est la palette de commandes de Slate, d'où l'écart avec la demande).

## 3. Fait et testé
Gras, italique, souligné, barré, indice/exposant (exclusifs), code en ligne ; couleur du texte (palette, HEX validé, retrait) ; surlignage multicolore (palette, HEX, retrait) ; polices (4 familles locales/système, aucune police distante) ; tailles prédéfinies + personnalisée ; titres 1 à 6 ; alignement gauche/centre/droite/justifié ; interligne ; listes à puces/numérotées/tâches avec retrait ; citation ; préformaté ; lien (http/https/mailto seulement) ; tableau 3×3 avec en-tête ; suppression du formatage (tout / une couleur) ; barre d'outils fixe réductible, états actifs, accessible (axe) ; menu `/` complété (titres 4–6, surlignage) ; statistiques (mots, caractères, sans espaces, paragraphes, temps de lecture) ; persistance : réouverture à l'identique (Yjs et JSON de secours).

## 3 bis. Tranche 2 : blocs et tableaux (fait et testé)
- **Encadrés typés** (note, information, avertissement, important, conseil, définition, résumé) : variante validée dans une liste blanche, étiquette traduite affichée, changement de type et retrait depuis une barre contextuelle ; les anciens encadrés sans type deviennent « note ». Entrées du menu `/` pour chacun.
- **Bloc repliable** (accordéon) : extension officielle Tiptap `details` (état ouvert/fermé conservé), bouton avec libellé traduit.
- **Sommaire** : bloc dont la liste (H1 à H6, hiérarchie) est recalculée à chaque modification et cliquable ; seule la présence du bloc est stockée ; texte des titres jamais interprété comme HTML.
- **Tableaux** : redimensionnement des colonnes, barre contextuelle (ligne/colonne avant-après, suppression, fusion et division de cellules, ligne et colonne d'en-tête, fond de cellule validé, suppression du tableau), navigation Tab native, fond et largeurs conservés à la réouverture, HTML collé nettoyé. Les tableaux documentaires restent distincts des bases de données.

## 3 ter. Tranche 3 : images et code (fait et testé)
- **Images** : fichiers dans `<données>/media/<sha256>.<ext>` (Rust, `media.rs`) ; le document ne contient que l'**empreinte** (jamais de base64). Type déduit des octets (PNG, JPEG, GIF, WebP ; **SVG refusé**), 20 Mo maximum, écriture atomique, empreinte revérifiée à la lecture, empreinte exigée en hexadécimal strict (pas de traversée de chemin). Insertion par bouton, menu `/`, collage et glisser-déposer ; légende éditable ; texte alternatif ; alignement (gauche, centre, droite, largeur du contenu, pleine largeur) ; largeur (auto, 25/50/75/100 %) ; remplacement ; suppression ; aperçu en grand.
- **Blocs de code** : 14 langages + texte brut (liste blanche), coloration syntaxique (lowlight), numéros de ligne, copie, repli, défilement horizontal ; le code reste du texte.

## 3 quater. Tranche 4 : recherche et versions (fait et testé)
- **Recherche et remplacement** (Ctrl/Cmd+F ou bouton) : occurrences repérées à travers les marques de mise en forme, compteur « n / total », navigation circulaire (Entrée, Maj+Entrée), casse, mots entiers (limites de mot Unicode), recherche **littérale** (aucune expression régulière), remplacer / tout remplacer en conservant la mise en forme et annulable, Échap pour fermer. Le calcul de 5 000 paragraphes prend ~20 ms ; le rendu des surlignages n'a pas été chronométré dans un navigateur réel (sous jsdom : ~2 s pour 5 000 occurrences).
- **Versions** (migration 0008, `versions.rs`) : version automatique au plus toutes les 10 min si le contenu a changé ; versions manuelles nommées ; conservation : toutes les automatiques des dernières 24 h, une par jour pendant 30 jours, 100 au plus, les manuelles et « avant restauration » ne sont jamais supprimées automatiquement ; suppression des versions avec la page purgée. Interface : liste, enregistrement, **comparaison ligne à ligne** avec le contenu actuel, restauration.
- **Restauration sûre** : l'état actuel est d'abord sauvegardé (raison « avant restauration ») ; si cette sauvegarde échoue, rien n'est restauré (testé) ; puis l'ancien contenu est appliqué comme une modification ordinaire, annulable avec Annuler.
- Auteur : l'adresse du compte connecté, sinon aucun (pas de multi-utilisateur local).

## 3 quinquies. Tranche 5 : modes d'écriture (fait et testé)
- **Largeur de lecture** (étroit, normal, large, pleine largeur) : préférence enregistrée (`pref.reading-width`, validée), menu « Affichage » de la page et 4 commandes de la palette.
- **Mode lecture** : le document devient non modifiable (`contenteditable=false`), barres d'outils, poignées de glisser, barre flottante et remplacement masqués, titre en lecture seule, restauration de version désactivée ; la hiérarchie (titres, listes, tableaux, code) reste affichée ; la recherche reste utilisable. Raccourci Ctrl/Cmd+Maj+E.
- **Mode focus** : barre latérale, en-tête, fil d'Ariane et boutons secondaires masqués, document centré ; l'édition, les raccourcis et la barre de mise en forme restent disponibles ; un bouton flottant (avec l'état d'enregistrement et le « Réessayer » en cas d'échec) et Échap permettent de revenir (Échap ne quitte pas le focus s'il ferme déjà une recherche, un menu ou un dialogue). Ctrl/Cmd+Maj+F. Quitter la page quitte le focus.
- Ces deux modes ne sont **pas mémorisés** : l'application redémarre toujours en mode édition (un mode lecture mémorisé ressemblerait à un document verrouillé).

## 3 sexies. Tranche 6 : commentaires (fait et testé)
- **Ancrage** : une MARQUE du document (`comment`, identifiant de fil en UUID validé) portée par l'état Yjs. Elle suit le texte lors des insertions et suppressions, **y compris concurrentes** (test à deux copies Yjs : convergence et ancrage sur les mêmes mots), ne s'étend pas au texte tapé juste après, s'étend à l'intérieur, et plusieurs fils peuvent se chevaucher. Le copier-coller **ne duplique jamais** un commentaire (marques retirées à l'arrivée).
- **Fils et messages** (migration 0009, `comments.rs`) : création avec premier message, réponses, modification (marquée « modifié »), suppression d'un message (le dernier supprime le fil et son ancrage), résolution / réouverture avec auteur et date, suppression d'un fil. Limites : 5 000 caractères par message, 2 000 fils par page, 500 messages par fil. Suppression avec la page purgée. Création atomique ; si l'ancrage dans le texte échoue, le fil est retiré (pas de fil sans ancrage) ; si la sélection a changé pendant la saisie, la création est refusée.
- **Interface** : bouton « Commenter la sélection » (barre fixe et barre flottante), panneau latéral (ouverts / résolus avec compteurs, aller au passage, surlignage du passage actif et atténuation des résolus), clic sur un passage commenté, fils orphelins (texte supprimé) conservés avec leur citation, réponses possibles en lecture seule, création désactivée en lecture seule.
- Auteur : adresse du compte connecté, sinon « Vous ».

## 3 septies. Tranche 7 : collage et liens (fait et testé)
- **Liens** (`link.ts`) : seuls http(s), `mailto:` avec adresse valide et liens internes `slate://page/<uuid>` sont acceptés, **à la saisie, au collage et au chargement** (`javascript:`, `data:`, `file:`, `vbscript:`, schémas déguisés par des espaces, tabulations ou caractères invisibles, identifiants dans l'URL, URL > 2 000 caractères : refusés — 25 cas testés). La saisie est normalisée (`example.com` → `https://…`, `ada@x.org` → `mailto:`) avec aperçu de l'adresse finale. Dialogue : adresse, texte affiché (insertion sans sélection), choix d'une page de Slate. Carte du lien au curseur et au survol : ouvrir, copier l'adresse, modifier, retirer. Ouverture : Ctrl/Cmd + clic en édition, simple clic en lecture ; liens internes → navigation (page supprimée → message) ; externes → commande Rust `open_external` qui **revalide** l'adresse (http, https, mailto seulement) et ouvre le navigateur ou le client de messagerie du système. Les liens internes alimentent les rétroliens.
- **Collage** (`paste.ts`, `SmartPaste.ts`) : nettoyage avant analyse (scripts, styles, iframes, formulaires, SVG, objets, attributs `on*`, `class`/`id`, déclarations `mso-*`, commentaires conditionnels Word, éléments à espace de noms, conteneur « gras » de Google Docs, éléments cachés) ; couleur/taille/police posées sur un bloc descendues sur le texte ; **paragraphes de liste Word → vraies listes imbriquées**. Politique automatique : Word, Google Docs et Slate gardent leur mise en forme ; un site web est **normalisé** (structure et sémantique gardées ; couleurs, polices, tailles, surlignage, alignement, interligne et fonds de cellule retirés). Menu « Coller » : avec la mise en forme / formats compatibles seulement / texte brut (lecture du presse-papiers, message clair si l'autorisation est refusée). Ctrl/Cmd+Maj+V reste le collage en texte brut natif. Le texte brut n'est jamais interprété comme du HTML.

## 3 octies. Tranche 8 : listes et paragraphes (fait et testé)
- **Styles de liste** (valeurs validées, liste blanche) : puces ronde, creuse, carrée, tiret ; numérotation 1, a, A, i, I. Un style qui ne convient pas au type de liste est refusé ; un style étranger collé est ignoré. Sélecteur dans une barre contextuelle qui apparaît dans une liste, avec **monter / descendre l'élément** (aussi Alt+Maj+↑/↓ dans une liste ; hors liste, ce raccourci déplace toujours le bloc).
- **Listes de tâches** : barre de progression facultative par liste (cases imbriquées comprises, mise à jour à chaque case, `role="progressbar"` avec valeur et libellé annoncés) ; préférence **Tâches terminées : barré / non barré** (Réglages > Apparence). Entrée sur un élément vide sort de la liste, Tab / Maj+Tab indentent et désindentent.
- **Paragraphes et titres** : retrait gauche et retrait droit (1 à 8 niveaux de 1,5 rem), espace avant et après (0, 4, 8, 12, 16, 24, 32 px), réinitialisation. « Augmenter / diminuer le retrait » agit sur l'élément de liste dans une liste, sur le paragraphe ailleurs ; raccourcis Ctrl/Cmd+Alt+→ / ←. Les marges ne sont jamais prises d'un style collé : seules ces valeurs validées sont stockées.
- Choix de raccourcis : Ctrl/Cmd+[ et ] restent la navigation arrière/avant de Slate (donc pas utilisés pour le retrait) ; Tab ne retire pas le retrait d'un paragraphe ordinaire (il resterait piégé au clavier).

## 3 nonies. Barre masquable et menu du clic droit
- **Barre de mise en forme** : le bouton « Masquer la barre de mise en forme » la replie ; il reste une petite flèche au centre du haut du document pour la ramener. Le choix est une **préférence mémorisée** (`pref.toolbar-collapsed`), donc la barre reste masquée d'une page à l'autre et après redémarrage ; commande de la palette « Afficher / masquer la barre de mise en forme ».
- **Clic droit** (aussi la touche Menu / Maj+F10, c'est le même événement) : menu d'actions rapides adapté au contexte — Couper, Copier, Coller (3 modes), Tout sélectionner ; gras, italique, souligné, barré, code (cochés quand actifs) ; couleur du texte, surlignage, effacer le formatage ; sous-menus Paragraphe (styles, alignements, retraits), Listes, Insérer (tableau, image, séparateur, encadré, bloc repliable, sommaire) ; lien (modifier, ouvrir, copier l'adresse, retirer) ; Commenter ; sous-menu Tableau dans un tableau ; supprimer l'image sur une image. En lecture seule : seulement Copier et Tout sélectionner (+ actions de lien). Un clic droit hors de la sélection place d'abord le curseur.
- Limite connue des tests : sous jsdom, les éléments de sous-menu sont activés par clic direct (la « zone de grâce » du pointeur de Radix referme le sous-menu pendant un geste simulé) ; le vrai geste à la souris n'a pas été vérifié par un test automatique.

## 4. Pas encore fait (honnêtement)
Retrait de première ligne, numérotation continue entre deux listes séparées, déplacement de lignes de tableau, mise en forme par cellule autre que le fond (gras etc. via la barre normale seulement), table des matières latérale/masquable, vidéos et fichiers intégrés, **envoi des images vers Supabase Storage** (dépend de la synchronisation et des comptes connectés à un espace), nettoyage des images devenues inutilisées (les fichiers restent sur le disque), redimensionnement à la souris (largeurs par paliers seulement), recadrage, **mentions de personnes dans les commentaires** (pas de membres tant que les comptes ne sont pas reliés à des espaces partagés), notifications de commentaires, permissions de suppression par rôle (un seul utilisateur local pour l'instant), historique des modifications d'un message (seule la date de dernière modification est conservée), rattachement d'un commentaire quand le passage est déplacé par couper-coller (le fil devient orphelin), présence et curseurs collaboratifs (la couche Yjs existe, pas le transport), synchronisation cloud, version de schéma de document explicite, indice/exposant dans la barre flottante. Équations et intégrations : absentes.

Limites du collage : les images contenues dans le HTML collé (`<img src="data:…">` de Word, images distantes) sont ignorées — seules les images collées comme fichiers sont enregistrées ; les niveaux de liste Word sont reconstruits à partir de `mso-list` (testé sur un exemple fabriqué, pas sur de vrais documents Word) ; le tableau Word/Docs complexe (cellules fusionnées imbriquées) n'a pas été éprouvé.
